# 实现工作流

输入：目标行为或已确认的设计、修改范围及验收场景。

1. 检查已有变更，按 [代码参考](../code-map.md) 阅读生产者、消费者与测试。接口或状态语义尚不明确时，先执行 [设计工作流](design.md) 的相关步骤。
2. 沿选定链路实现改动，保持 [仓库约束](../../AGENTS.md)，应用 [代码实现规范](../coding-standards.md) 的相关规则。跨层字段变更同步处理序列化、Python 接口及示例；涉及有状态行为时覆盖失败和取消路径。
3. 为受影响行为增加或调整有意义的测试。用户可见接口或能力边界改变时，调用 [文档工作流](document.md) 更新对应说明。
4. 按代码实现规范的验收项自查，调用 [验证工作流](verify.md)。验证失败时进入 [诊断工作流](debug.md)，修复后返回验证。

改变已有技术图覆盖的职责、调用关系或关闭状态时，调用 [技术图工作流](diagram.md) 同步图与证据，再完成交付。

完成条件：请求的行为已实现，相关验证通过，接口与说明一致。存在无法完成的检查时，明确交付限制，不将未验证项报告为通过。

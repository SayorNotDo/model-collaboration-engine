# 文档工作流

输入：需要新增或调整的说明、规则、工作流，以及目标读者。

1. 阅读现有文档与相关实现，确认本次要改变的事实或操作行为。维护代理规则时应用当前可用的代理文档写作指引。
2. 选择内容归属：领域术语与概念关系放根目录 `CONTEXTS.md`，全局约束放 `AGENTS.md`，代码实现规则放 `coding-standards.md`，任务选择放 `task-router.md`，执行步骤放 `workflows/`，代码定位放 `code-map.md`，检查命令放 `.agent/README.md`，用户用法放根目录 README。
3. 修改对应文档并同步入口链接。工作流写明输入、执行步骤、完成条件及必要的后续流程；路由变更确保每个分支指向实际存在的工作流。
4. 术语或职责边界变化时，联动检查 [CONTEXTS.md](../../CONTEXTS.md) 的概念定义、[AGENTS.md](../../AGENTS.md) 的工作约束和 [README.md](../../README.md) 的用户说明；仅更新受影响内容，其他位置通过引用保持一致。文档与代码冲突时按 AGENTS.md 的“跨层变更”规则确定预期行为。
5. 调用 [验证工作流](verify.md) 的文档检查分支，检查引用、源码事实及新增文件。作为其他任务的子步骤时，将结果交回原工作流。

技术图源文件、产物与证据归属 `docs/diagrams/`；新增或更新图调用 [技术图工作流](diagram.md)。图索引维护覆盖范围和验收状态，CONTEXTS 保留术语、概念关系与流程链接，避免复制操作步骤。

完成条件：目标说明准确，入口可达，相关文档指引一致；操作规则具有可执行步骤和可判断的完成条件。

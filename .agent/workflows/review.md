# 审查工作流

输入：待审查的提交、分支、工作区变更或明确的代码范围，以及相关需求。

1. 确定比较基准与审查范围，阅读需求、差异及 [仓库约束](../../AGENTS.md)。范围不足以开展审查时先明确缺失项。
2. 通过 [代码参考](../code-map.md) 追踪变更涉及的调用方和数据消费者，检查行为是否满足需求，并按 [代码实现规范](../coding-standards.md) 检查适用规则；重点核对受影响的预算、取消、权限和持久化语义。
3. 对候选问题检查具体触发条件与影响，必要时调用 [验证工作流](verify.md) 获取证据。将确定的问题与尚未验证的风险分开。
4. 按影响优先级报告问题、代码位置与复现条件；没有发现问题时说明审查范围和验证限制。用户同时要求修复时，将已确认问题传给 [实现工作流](implement.md)。

完成条件：审查范围内的相关链路已检查，发现可定位且有依据；单独审查任务以报告交付。

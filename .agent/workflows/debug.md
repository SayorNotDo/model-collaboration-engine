# 诊断工作流

输入：故障表现、期望结果及可用的复现条件。

1. 记录触发条件与错误结果，优先形成最小复现或失败用例。暂不能复现时保留已有日志与条件差异，明确证据缺口。
2. 按 [代码参考](../code-map.md) 沿相关链路追踪状态和数据。提出可检验的原因假设，用测试、日志或局部检查逐项验证；性能问题记录可比较的测量条件与结果。
3. 确认原因后，说明其如何产生该故障。仅要求诊断时在此交付；已要求修复时，将原因、受影响范围和回归场景传给 [实现工作流](implement.md)。
4. 修复后由 [验证工作流](verify.md) 复核原复现与相关回归路径。失败仍在时回到原因验证，更新假设。

完成条件：诊断结论有证据支撑；修复任务还需原故障消失且相关验证通过。复现受阻时报告阻塞条件与已排查范围。

# 设计工作流

输入：目标行为、用户约束及当前实现。

1. 通过 [代码参考](../code-map.md) 确认现有接口与调用链，列出需要改变的行为及兼容要求。事实未明时先调用 [调查工作流](investigate.md)。
2. 定义模块职责、输入输出、状态转换与失败语义。涉及执行流程时明确预算、工具权限、取消、截止时间和持久化边界；有实质取舍时比较方案并给出选择理由。

   新增或拆分模块时，按 [代码结构规范](../coding-standards.md#代码结构) 明确目录归属、依赖方向、状态所有者与公共导出；已有结构能承载目标时优先复用。
3. 将设计拆成可实现步骤，为每步指定影响范围及可观察的验收场景。按用户要求交付方案；用户已要求实现时，直接将设计传给 [实现工作流](implement.md)。

用户要求技术图，或设计改变已有图所覆盖的关系时，调用 [技术图工作流](diagram.md)，明确区分目标设计与当前实现。

完成条件：接口、边界、失败路径和验收场景足以指导实现；尚未决定的关键事项明确列出，不以未确认假设冒充结论。

# 验证工作流

输入：待验证的行为、变更范围、验收场景及已有检查结果。

1. 选择相关场景；代码链路和回归参考见 [代码参考](../code-map.md)。已有检查仍对应当前代码且覆盖目标时保留其证据。
2. 按 [本地验证流程](../README.md) 执行适用分支：Rust 行为检查、重建扩展后的 Python 检查，或纯文档检查。共享构建目录的命令按规定顺序执行。
3. 检查每项结果与退出码，区分产品失败、环境阻塞和未执行项。发现失败时调用 [诊断工作流](debug.md)；有修复授权则修复后重新验证受影响项，否则报告证据。

   技术图使用 [本地验证流程](../README.md) 的技术图分支；核对 JSON、HTML 与检查回执的哈希一致，并分别记录结构、浏览器、视觉结果。已有图变化后旧回执不能直接沿用。
4. 汇总已执行检查、结果及未覆盖范围。作为其他工作流的子步骤时返回验证结论，由调用方完成交付。

完成条件：选定验收场景都有明确结果；通过项有实际执行或仍有效的检查证据，失败和阻塞均被明确报告。离线模拟与真实供应商联调分别说明。

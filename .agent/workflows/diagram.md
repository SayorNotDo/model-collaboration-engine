# 技术图工作流

输入：读者要理解的问题、当前实现或目标设计、相关源码与已有技术图。

1. 阅读当前可用的 `archify` 技能及 [技术图索引](../../docs/diagrams/README.md)。从 [代码参考](../code-map.md) 定位实现，依据源码核实参与方、关系与异常路径；未实现能力明确标为设计，不画成当前事实。
2. 选择图型：模块关系用 architecture，过程用 workflow，调用时序用 sequence，数据传递用 dataflow，状态转换用 lifecycle。读取对应 schema 和示例，按技能要求编写最小候选；领域用语遵循 [CONTEXTS.md](../../CONTEXTS.md)。
3. 在 `docs/diagrams/` 维护 JSON 编辑源和独立 HTML 产物。用 `source-map.json` 记录节点或状态对应的源码路径及内容哈希；工作区未提交变更不得冒充固定提交证据。概念或关系变化后更新证据映射。
4. 按 [验证命令](../README.md#技术图检查) 校验、修复并交付冻结的源文件。仅修改 JSON，通过生成器更新 HTML；保留 delivery 回执。依照技能规定的修复上限停止无效迭代并披露限制。
5. 对交付的同一 HTML 收集浏览器回执与截图，再实际查看截图，分别记录结构检查、浏览器证据、视觉审查和修正轮数。源文件变化后重新生成并重做受影响检查；不得手改回执使失败成为通过。
6. 更新技术图索引与 `review.json`，核对产物和源码哈希。职责或术语变化时调用 [文档工作流](document.md)，同步受影响的 CONTEXTS、AGENTS 或用户文档，然后返回原任务。

完成条件：图义与所声明证据相符，入口可达，源文件可再生成；三类验收结论及规格/产物 SHA-256、字节数可追踪。检查失败或未执行时明确标为待完成，不能将部分通过报告为完整验收。

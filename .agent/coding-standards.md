# 代码实现规范

新增、修改或审查代码时，按涉及的语言与链路应用本规范。适用于本次变更及其直接影响的接口；发现范围外的历史问题时记录具体影响，避免顺带重写无关模块。业务不变量以 [AGENTS.md](../AGENTS.md) 为准，术语见 [CONTEXTS.md](../CONTEXTS.md)，验证命令统一见 [本地验证流程](README.md)。

## 模块与接口

- 按业务职责组织函数和类型。新增抽象需对应实际的替换点、共享规则或复杂度隔离；局部行为优先放在拥有该职责的模块，避免把业务逻辑聚集到通用工具文件。
- 默认保持实现私有；扩大可见性前确认实际调用方。公共接口说明输入、返回值、错误和资源生命周期，异步接口额外说明取消后的行为。
- 参数、状态和结果优先使用明确类型；动态 JSON 用于协议、持久化证据及语言边界。解析后验证再进入执行逻辑，区分字段缺失、`null`、空值和数值零。
- 使用已有领域名称；计量字段带单位或明确约定，例如 `deadline_ms`、`input_tokens`。影响序列化的重命名按公共契约变更处理。

## 代码结构

### 目录与职责归属

沿用现有 Rust crate 与 Python 包结构，先在所属模块内组织新能力；出现独立职责或触发文件大小阈值时再拆子模块。具体代码位置以 [代码参考](code-map.md) 为准。

| 位置 | 允许承担的职责 |
| --- | --- |
| `src/` | Rust 契约、执行编排、决策规则及基础设施实现 |
| `python/model_collaboration_engine/` | Python 公共入口、asyncio 生命周期和宿主交互 |
| `tests/`、`tests/python/` | Rust 跨模块与 Python 原生集成测试；测试辅助代码留在测试范围 |
| `examples/` | 可运行用法与配置样例，通过公共接口演示能力 |
| `docs/` | 设计说明、技术图源及其生成产物 |
| `.agent/` | 仓库工作流与规范，不放产品运行时代码 |

### 模块依赖方向

- `contracts` 提供共享数据契约和边界校验，业务契约不反向调用执行引擎、Python 绑定或具体模型服务。协议专用类型留在适配器，模块私有类型留在使用它的模块。
- `router`、`strategy` 处理选择与评价规则，通过显式输入获得预算、健康统计及任务上下文；规则模块不直接发起网络请求、读取数据库或执行宿主工具。
- `engine` 组织执行，通过 `ModelAdapter`、`Store`、`ToolExecutor` 等已有接口访问外部能力。适配器不承接全局预算或策略编排；存储不调用模型服务。
- `bindings` 依赖引擎公共能力完成 Python 桥接；核心业务模块保持可在未启用 Python 特性时使用。宿主工具经接口注入，核心不导入具体宿主实现。
- 具体实现可由现有 `Engine::open` 统一组装，测试通过 `with_components` 注入替身。只有出现实际替换或独立复用需求时才引入新的 trait、crate 或组装层。
- 新依赖保持单向且可解释。发生模块相互引用或 Python 循环导入时，先调整职责、提取最小共享契约或通过已有接口传递能力；不通过运行时延迟导入掩盖结构问题。

### 子模块与导出

- Rust 拆分采用 `<module>.rs` 作为入口、`<module>/` 放置内部子模块；已有模块若采用 `mod.rs` 则保持该模块约定。同名模块的两种入口形式不能同时存在。
- 模块入口集中声明子模块、稳定导出和必要组装，具体逻辑放在有业务名称的子模块中。内部实现使用私有、`pub(super)` 或必要的 `pub(crate)`；跨模块调用通过明确的导出接口，避免依赖其他模块的内部路径。
- Python 的 `__init__.py` 保留简洁的公共入口与导出；拆分实现时使用有职责名称的私有模块，如 `_run.py`，保持已有包级导入方式兼容。共享类型不得依赖包入口，以免形成导入环。
- 模块状态由明确的所有者管理，通过参数或接口提供依赖；配置加载、运行状态与外部资源不隐藏在可变全局对象中。
- 共享辅助代码在实际存在多个调用方且语义一致时提取，放入拥有该领域职责的模块。测试夹具可以共用，生产模块不依赖测试或示例代码。

结构调整完成后，检查公共导入路径、特性开关、模块可见性和测试发现方式；更新受影响的代码参考与技术图。新增目录必须能说明其独立职责和调用方，不预建暂无实现的分层目录。

## Rust

- 内部状态与互斥结果优先用 `struct` / `enum` 表达，通过构造或转换集中校验不变量；动态 JSON 在边界解析后收敛为明确类型。为金额或身份引入 newtype 时，应能阻止实际的单位或身份混用，并同步核对序列化契约。
- 可预期失败返回项目 `Result<T>` / `EngineError`。错误类别用于调用方判断，消息说明失败条件；补充任务身份及必要的结构化详情，避免把凭证或完整请求内容写入错误。
- 来自配置、网络、宿主和数据库的数据通过可失败解析处理。生产路径中的 `unwrap` / `expect` 仅用于能够说明依据的内部不变量；新增或修改该路径时检查失败是否可能由外部输入触发。
- 费用、计数和边界转换使用受检运算与转换。只有业务语义明确要求截断到边界时才使用饱和运算；跨 SQLite 有符号整数边界时检查范围。
- 同步锁用于短暂内存访问，释放后再 `.await`。异步锁若跨等待持有，明确串行化目的、锁顺序与取消时的释放方式；检查回调是否会重新进入同一等待链路。
- 按需借用数据；仅在任务所有权、通道或 FFI 生命周期确实需要时克隆或使用 `Arc`。对多个字段构成的不变量，在同一同步边界内更新。
- 修改含 `select!`、超时、任务中止或后台派发的路径时，逐个检查 future 被丢弃的位置：已经预留、已经派发和等待结算分别由谁接管。`Drop` 只承担同步释放或发出信号，必须等待的异步结算和终态写入由明确持有的任务或显式关闭流程完成；直接丢弃 future 的恢复边界写入公共接口说明。
- Rust 后台任务明确句柄所有者、panic/错误的接收方及关闭时的等待方式。阻塞 I/O 或长时间 CPU 工作放入适当执行器，并说明取消是否能停止底层工作；发送取消信号不等于工作已经停止。

## Python

- 新增或修改的公共 Python 方法提供参数与返回类型标注；结构稳定的字典优先用 `TypedDict` 描述，回调或可替换对象按实际需要使用 `Callable` / `Protocol`。动态边界允许 `Any`，进入内部逻辑后尽量收窄；类型标注不替代运行时校验。字典接口沿用 Rust 序列化约定，文档说明字段缺失与 `None` 的区别。
- Python 包装层处理 asyncio 生命周期和宿主交互，业务判定保持在负责该规则的 Rust 模块。FFI 只做数据转换、任务桥接与错误映射。
- 阻塞工作放入适当的工作线程或原生执行器。每个后台任务明确谁等待结果、传播异常和完成清理，避免只创建任务而遗失其句柄。
- 生命周期一致、失败时应共同取消的子任务优先考虑 `TaskGroup`。原生结算等必须继续收尾的任务可显式管理，但应保存强引用并说明等待责任；调整并发组织前检查兄弟任务取消是否会破坏账务及回调清理。
- 捕获取消异常时明确清理范围，并在清理完成后传播取消。`asyncio.shield()` 不会阻止调用者收到取消异常；受保护任务仍须保留引用并等待，重复取消也不能丢失清理责任。聚合任务使用 `return_exceptions=True` 时，说明异常由哪个结果通道处理或为何允许忽略。
- 优先捕获具体异常；需要在宿主回调边界捕获 `Exception` 时，明确错误映射及取消处理。静态类型检查按已配置的工具与范围执行；新增检查器时同步配置依赖和本地验证入口，不能将标注完整等同于类型检查通过。
- 使用上下文管理器或 `try/finally` 管理资源；部分初始化失败时同样释放已取得的资源。

## PyO3 与异步运行时边界

- Python 回调在宿主 asyncio 循环执行，Rust 编排在原生异步运行时执行；使用项目所依赖版本支持的桥接 API 传递事件循环及必要上下文，不在宿主循环内嵌套启动事件循环。API 与线程要求以 Cargo 中的 PyO3 及异步桥接依赖版本为准。
- 在访问 Python 对象的合法解释器上下文内完成借用与转换。跨 `.await`、线程或后台任务优先传递拥有所有权的 Rust 数据；确需保留 Python 对象时，使用相应版本支持的拥有型句柄，并明确后续访问所需的解释器上下文。Python 借用对象不得逃逸其有效生命周期。
- 每条跨语言请求明确请求身份、响应通道、接收方退出后的处理与资源所有者。Python 取消传入 Rust 后，继续等待原生结果与宿主回调清理；Rust 错误映射保持可识别类别，通道关闭与失败也必须使等待方得到明确结果。

## 持久化与外部边界

- SQL 值使用参数绑定。一个业务动作需要共同成功的账本、状态和审计更新放入同一事务；组合读取需要一致证据时使用同一读事务。
- 事务中只完成数据库工作，模型请求与宿主回调在事务外执行。新增查询考虑数据量、排序稳定性和索引；全量查询在公共说明中写明规模限制，扩展大规模用途时设计分页。
- 外部调用前明确准入、超时和失败后的记账责任。新增重试必须说明可重试错误、次数上限，以及重复执行的副作用和计费处理。
- 对输入大小、队列、批次和迭代设置与业务需求对应的上限，复用已有配置。异常路径也必须能够结束或返回明确的未完成状态。

## 可读性

- 一个函数表达一个完整业务动作，主路径按执行顺序展开。输入拒绝与错误条件优先提前返回；连续条件或循环嵌套超过 3 层时，检查是否能通过命名条件、提前返回或提取职责降低复杂度。
- 变量名表达领域含义，布尔值表达可判断的条件；单字母名称限于短循环或局部数学表达式。复杂条件拆成有意义的局部变量，避免重复求值带副作用的表达式。
- SQL、查询映射、链式调用和错误处理按逻辑步骤分行。即使格式化器没有展开，也应避免把多个业务动作、多个解析步骤或事务操作压在同一行。
- 注释解释不变量、取舍、顺序要求及非直观原因；公共接口文档描述调用者需要知道的语义。临时方案用 `TODO` 标明具体缺口和移除条件，有关联任务时附引用。
- 抽取函数应减少读者需要同时理解的状态；保留事务、锁与清理的完整边界，避免为了缩短函数而传递大量可变状态。

## 代码风格

- 文件使用 UTF-8；换行方式遵循仓库配置，局部修改保留既有换行，不因格式统一重写整个文件。
- Rust 格式以 rustfmt 为准；类型与 trait 使用 `PascalCase`，模块、函数和变量使用 `snake_case`，常量使用 `SCREAMING_SNAKE_CASE`。生产代码使用显式导入，新增通配导入需有具体理由。
- Python 使用 4 空格缩进；类名使用 `PascalCase`，函数、方法、变量使用 `snake_case`，常量使用 `SCREAMING_SNAKE_CASE`。导入按标准库、第三方、本包分组，组间留空行；沿用现有双引号风格。
- Rust 行宽遵循 rustfmt 配置；Python 代码行以不超过 100 字符为目标，长参数与复合表达式使用括号分行。不可拆的 URL、协议样本和字符串可保留原样。
- 文件通常按模块说明、导入、常量与类型、对外入口、内部实现组织；紧密相关的类型与实现相邻放置。测试按行为分组，共用辅助代码放在对应测试模块可发现的位置。
- 新增格式化器或检查器时，同时配置实际执行入口及适用范围。尚未配置自动检查的规则在实现自查与审查中执行，不将其描述为 CI 已强制执行。
- 当前 Rust 使用 Cargo 中配置的 Clippy 规则与 rustfmt；Python 使用 pyproject.toml 中配置的 Ruff 规则。具体范围、安装及执行命令见[本地验证流程](README.md)；新增 lint 忽略须限定到必要规则和最小范围，并说明原因。

## 文件与函数大小

以下阈值用于发现职责过度集中，按物理行数统计，包含空行、注释和文档字符串。适用于手写 Rust/Python 源码及测试文件；生成的 HTML、锁文件、第三方代码与数据样本不计入。

| 对象 | 目标 | 超出后的要求 |
| --- | --- | --- |
| 生产源码文件 | 通常不超过 400 行 | 超过 400 行检查职责边界；超过 600 行的新增或实质扩展文件应拆分，必要保留时记录原因和验证证据 |
| 测试文件 | 通常不超过 600 行 | 超过 600 行按功能或场景检查分组；超过 800 行的新增或实质扩展文件应拆分，避免复制测试夹具 |
| 函数或方法 | 通常不超过 60 行 | 超过 60 行检查业务步骤；超过 100 行说明保持完整的必要性，或提取具有独立职责的步骤 |

- 按协议适配、执行阶段、持久化业务动作或测试场景拆分，文件名体现职责；避免使用 `part1`、`part2` 或无明确职责的 `misc` 分片。
- 拆分后保持对外接口与业务语义，内部模块采用满足调用需要的最小可见性；检查循环依赖、事务范围、锁顺序和取消清理路径。
- 历史超限文件在新增独立职责、大幅扩展已有逻辑或修改超限函数时评估拆分，并在交付中说明结果。小范围修复不要求全文件重构；超限处减少空行、压缩语句不算完成整改。

## 依赖

- 新增依赖先检查现有依赖能否满足需求；说明用途、特性开关及构建影响，并更新对应清单和锁文件。版本兼容范围以项目配置为准。

## 验收

实现完成或审查交付前，确认以下各项在变更范围内成立：

1. 接口的调用方、输入校验、序列化和错误处理一致，兼容性变化有明确说明。
2. 受影响的取消、超时、异常及资源释放路径均已检查；有状态行为以结果、调用次数或账本状态验证。
3. 并发测试优先使用事件、通知或通道控制交错；避免用固定睡眠猜测执行进度，并为等待设置合理的失败上限。
4. 使用真实业务场景或最小故障复现验证变化；测试不只重复实现步骤。适用检查按本地验证流程执行，未执行项及失败结果如实记录。
5. 用户说明、领域定义和技术图按受影响范围更新。差异中不混入无关格式化、生成文件手改或临时调试产物。
6. 检查变更后的手写源码和测试文件行数；对触发阈值的文件、函数及深层嵌套记录拆分结果或保留理由，核对可读性和语言风格要求。
7. 新增或拆分模块时，确认职责归属、依赖方向、状态所有者与公共导出；检查循环依赖及生产代码对测试辅助代码的反向依赖。
8. 涉及异步或跨语言变更时，核对 future 丢弃点、后台任务句柄、异常接收方及跨运行时对象生命周期；按受影响路径验证重复取消、通道关闭和部分初始化失败后的清理。类型及风格工具的通过结论须注明实际执行范围。

存在必要的规范偏离时，说明具体规则、技术原因、影响与验证证据；已有任务授权足以决定的实现取舍直接处理。业务不变量变化仍按 AGENTS.md 的跨层变更规则确定预期行为。

## 语言实践参考

需要确认语言或库行为时查阅与项目依赖版本匹配的官方文档；项目业务不变量继续以 AGENTS.md 为准。

- [Rust API Guidelines](https://rust-lang.github.io/api-guidelines/checklist.html)：类型、接口与失败条件文档。
- [Python asyncio 任务与取消](https://docs.python.org/3.12/library/asyncio-task.html)：项目最低 Python 版本的任务、TaskGroup 与 shield 语义；使用更高版本特性前核对 pyproject.toml。
- [PyO3 异步集成](https://pyo3.rs/main/ecosystem/async-await.html)：双运行时协作的入口；具体 API 应切换到项目依赖版本核对。

# 任务工作流路由

根据用户任务选择并调用工作流。“调用”指读取对应工作流文件并按其步骤执行；本文件负责选择、组合与切换，具体步骤由工作流定义。

## 路由步骤

1. 识别用户要求的结果、允许的改动范围和当前任务进度。用户明确指定工作流时优先使用该工作流，否则按下表选择；依据任务意图，不按单个关键词匹配。
2. 读取所选工作流文件，简短说明本次采用的流程并执行。已有步骤完成且证据仍有效时，从未完成步骤继续。
3. 按工作流的完成条件验收。需要后续工作流时传递目标、已确认事实、变更范围与验证结果，然后继续执行用户已要求的工作。

## 任务 → 工作流

| 用户要求的结果 | 调用工作流 | 典型任务 |
| --- | --- | --- |
| 了解现状、解释代码或查明事实 | [调查工作流](workflows/investigate.md) | 当前进度、调用链说明、技术资料核实 |
| 形成设计、接口方案或实施计划 | [设计工作流](workflows/design.md) | 设计恢复机制、比较方案、划分模块职责 |
| 梳理或更新架构、调用链、数据流或状态技术图 | [技术图工作流](workflows/diagram.md) | 使用 archify 绘制架构、关闭生命周期、设计流程 |
| 新增能力、重构或改变既有行为 | [实现工作流](workflows/implement.md) | 增加工具支持、调整接口、补充测试能力 |
| 定位或修复已有故障、性能回退 | [诊断工作流](workflows/debug.md) | 取消失效、重复计费、测试失败、执行变慢 |
| 评估指定代码或变更的问题 | [审查工作流](workflows/review.md) | 审查分支、检查未提交修改、评审接口实现 |
| 创建或更新文档、代理规则或工作流 | [文档工作流](workflows/document.md) | 更新 README、AGENTS.md、任务路由与工作流 |
| 运行检查并确认某项行为 | [验证工作流](workflows/verify.md) | 运行测试、验证构建、复核修复结果 |

## 组合与切换

- “设计并实现”：设计 → 实现 → 验证。设计阶段产出的接口、约束和验收场景作为实现输入；只要求方案时，在设计完成后交付。
- “修复故障”：诊断 → 实现修复 → 验证原复现与回归场景。只要求诊断时交付原因、证据及修复建议。
- “审查并修复”：审查 → 实现已确认的问题修复 → 验证。单独审查任务交付发现，不自行扩展为修改任务。
- 实现附带的接口说明更新，调用文档工作流处理受影响内容；完成后回到原工作流的验收步骤。
- 技术图与规则更新：技术图 → 文档 → 验证。设计或实现改变已有图所覆盖的关系时，调用技术图工作流更新受影响图；完成后返回原流程。单纯解释一个局部事实不必新增图。
- 验证发现失败：进入诊断；已获修复授权时继续修复并重新验证，否则报告失败证据及影响。
- 多个独立目标按依赖顺序分别路由；混合任务保留所有已要求目标。目标不明确时先调查可确认事实，仅询问影响后续执行的缺失信息。

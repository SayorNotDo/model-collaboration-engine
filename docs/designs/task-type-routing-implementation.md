本记录中的双入口兼容决策已被用户确认的 [统一执行路径](execution-unification.md) 取代。下文保留当时实现与验证证据，不代表当前接口。

本批以 `feat/planning-submissions` 的 A+B 实现为基础，工作分支为 `feat/task-type-routing`。
实现 [规划与路由设计](planner-routing-design.md) 的 C；不包含 D 的持久化反馈、外部榜单导入或自动重新规划。

## 实现决策

- 配置可选，先覆盖带 EffectivePlan 的提交执行；旧 TaskSpec/run 以及规划路由不改变算法。这样旧自定义 Store 不必实现保存画像的方法。
- 画像、父类型、角色映射与类型权重共享一个配置版本。模型/验收版本错配属于缺失，重复完整键属于配置错误；不混合不同验收定义。
- `contracts/profiles` 拥有配置及校验，`router/profiles` 拥有纯解析与快照，Engine 的每任务 RunContext 拥有执行快照。没有新数据库表、网络访问或可变全局状态。
- 先校验计划、再应用宿主角色映射、固定快照、原子保存计划与 planned 检查点，随后执行。保存失败不会派发执行模型。
- 画像 Q 使用宿主静态证据。端点价格/延迟/可靠性/不确定性仍来自独立模型字段；临时 Health 可以影响可靠性，但不改变画像质量。
- 保存实际采用的画像证据与候选配置，避免仅记版本号却无法重建评分输入。快照摘要关联每次尝试；复算使用保存的有效任务、当次输入和 Health，不读取最新配置。
- 启用现有 serde_json 的 `float_roundtrip` 特性，不增加新依赖。256 组固定伪随机先验测试发现默认浮点读取会使快照摘要改变；启用精确往返后要求 JSON 保存/读取保持数值和摘要一致。
- 评分时间固定为快照时间，以复现延迟归一化及不可用判断；实时 deadline、预算与调用次数仍由现有准入和派发检查保障。这个选择不是可用性监控器，任务中不会刷新冷却状态。
- 级联门槛使用最终产物那次调用选中的 Q（工具续写或换模时返回最终模型的质量），与候选硬过滤和质量评分一致。评审只改变画像查询标签，不改变实际节点身份或工具权限。

## 验收与兼容

Rust 回归覆盖类型切换后的排序、精确/父级/general/全局回退、模型/验收/角色隔离、静态后验、
类型/父级权重、快照序列化后复算、硬约束、非法配置、级联跨模型、critic 默认及宿主映射、
规划仍在全局池、取消后快照和未知费用保留。Python 使用两个本地 HTTP/SSE 端点，覆盖 submit、
stream_submission、带画像配置的旧 run，以及配置失败前不发出 HTTP 请求。

现有 schema 1 和旧计划仍可读。`RoutingDecision` 新增证据字段有 serde 默认值，旧记录可解码。
Python 字典配置缺省兼容；Rust 直接构造 Config/RoutingDecision 字面量的调用方需要提供新增字段。
纯路由复算不生成真实模型输出，不执行工具，不自动恢复任务。未验证真实供应商。

模块大小：新增生产模块保持低于 400 行；既有 router 的硬过滤/评分循环保留在同一函数，
以避免画像路径与旧路径各维护一套约束；它超过 100 行，使用相同回归验证两个入口。
新增测试按路由行为归组，夹具在 tests/routing 与既有 tests/planning 内，生产源码不依赖测试代码。

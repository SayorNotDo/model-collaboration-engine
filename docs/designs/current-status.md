## 设计落地

| 设计部分 | 当前实现 | 仍有边界 |
| --- | --- | --- |
| A：统一提交与计划契约 | `run/stream` 接收提交；保存原始提交、建议及有效计划 | 没有任意执行图、子任务并行或自动重规划 |
| B：受限规划 | disabled/auto/required、规划候选池和纯校验；共享账本、调用次数、截止时间及关闭清理 | 规划无工具权限；无效建议是否回退由配置决定 |
| C：任务类型与角色画像 | 每任务固定路由快照；按版本、类型、角色和验收隔离，缺失按层级回退 | 不自动抓取榜单，不学习新路由算法 |
| 任务适配路由 | 任务质量目标、独立成本/延迟尺度、schema 4 固定快照；确定性检查失败后要求严格 Q 改善 | 当前是单次调用价值；语义 critic 驱动的 cascade 与协作总成本预测尚未接入 |
| 外部榜单参考 | 通用 JSON/CSV 导入、显式版本映射；task-fit-v1 仅用于主评分平分裁决 | 不自动联网；不将名次视为质量概率；真实榜单尚未配置 |
| D：反馈与持久化指标 | 候选检查、critic 与宿主反馈分层保存；反馈幂等，后续任务使用新质量样本 | completed 不自动生成质量反馈；无自动恢复/重放；调用健康指标未自动更新所有路由先验 |
| 执行、预算与工具 | 三种有界策略；模型、工具、续写共享额度；未知费用保留预留；宿主显式异步工具 | 执行 ID 不保证跨任务 exactly-once；工具失败不自动重试 |
| 生命周期与证据 | 取消/超时清理、分阶段关闭、SSE 有界背压、恢复查询与有证据的对账 | 数据库仅接受 schema 2；不提供自动迁移或自动清库 |

## 指标规模基线

`metrics()` 在一致读事务中遍历全部调用并解析 JSON；新任务固定路由快照时也会读取指标。现有实现没有时间窗口或分页聚合。新增[离线基准](../../examples/benchmark_metrics.py)只生成临时模拟库，无模型请求，校验聚合调用数和已知费用后测量。

[本地测量](../../artifacts/metrics-baseline-20260916.json)：Windows 11、Python 3.13.1，每个规模一次预热、五次查询；每任务一次已结算调用，单一模型分组、无质量反馈。耗时随记录数明显增长，因此不能直接承诺大型库的提交延迟。该基准不覆盖多画像分组、真实大 JSON、并发写入或冷缓存；后续优化应在这些数据形状上复测，并保持反馈 revision 与一致性快照语义。

| 调用记录数 | 中位耗时 | 最大耗时 |
| ---: | ---: | ---: |
| 100 | 1.22 ms | 1.37 ms |
| 1,000 | 8.42 ms | 8.92 ms |
| 10,000 | 77.95 ms | 80.31 ms |

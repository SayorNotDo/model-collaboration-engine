# 任务适配选模与动态升级

状态：第一阶段的任务价值评分、选择偏好和确定性检查驱动升级已实现；语义 critic 升级与协作总成本预测仍是目标设计。

## 核心目标

先选择对当前任务预期质量与成本最合适的模型，再依据实际产出动态升级，以合理的总成本满足任务验收要求。

“合适”同时包含满足任务要求、产出质量高、成本合理。不能简化为最便宜、榜单最高或固定从弱到强。质量接近时优先较低成本；质量提升明显且符合任务要求时，较高成本可以合理。预算表示允许支出多少，不能直接代表用户愿意为质量提升支付多少。

补充确认：按任务质量要求衡量收益，按额外质量收益权衡成本；收益接近时优先低成本，实际不达标时动态升级。“接近”和“值得付费”须由可记录、可复算的任务质量要求与成本偏好定义，不能依赖模型名称或隐含强弱等级。

预算充足不意味着应花完预算；质量达到最低要求也不意味着必须选择最便宜模型。首轮选择时，精度、完整性等额外质量若对该任务有价值，可以支持较高成本；实际产出通过有效验收后仍按停止规则结束。

不设置强弱模型使用比例，也不为分流而刻意选择较差候选。如果证据表明强模型对所有当前任务都具有更好的质量与成本权衡，集中选择它是合理结果。需要避免的是评分尺度、宽松预算或榜单加分导致的无依据集中选择。

## 已确认行为

1. 先执行能力、上下文、模型、供应商、地域、权限和资源硬约束。
2. 初次选择使用当前任务相关的质量证据和成本估计；允许直接选择强模型。未知质量不视为零，外部名次不当作验收概率。
3. 实际产出必须接受评价。评价不达标且允许继续时，携带原任务、已有产物和缺陷反馈选择下一候选。
4. 升级表示有证据支持下一候选更适合解决当前质量缺陷；更贵或榜单更高本身不是充分证据。缺少具体缺陷画像时必须标识使用任务级证据回退，不能声称已理解并匹配缺陷。
5. 通过有效验收即结束，不为了追求绝对最佳质量无限升级。人工介入、缺失证据和不可接受结论按各自语义终止，不能一律当作可重试。
6. 所有生成、评审、模型续写和工具共用预算、调用次数、轮数与截止时间；取消、未知费用和关闭清理保持既有语义。
7. 没有更合适且可负担的候选时，明确返回未达标原因并保留最新产物及账务证据，不放宽约束或重复无限尝试。

## 方案取舍

| 方案 | 优点 | 与目标的关系 |
| --- | --- | --- |
| 固定弱模型起步、依次升级 | 简单且易预测 | 困难任务可能支付无效首轮费用，不作为统一规则 |
| 固定综合得分最高 | 当前已有，容易复算 | 缺少充分的任务粒度及成本尺度，可能长期集中选同一模型 |
| 任务相关质量与成本权衡，再按评价升级 | 同时支持简单任务经济执行和困难任务直接强模型 | 目标方向；需补齐校准证据和运行中质量评价 |

## 现有基础与缺口

- [路由](../../src/router.rs)已有硬约束与加权评分；成本惩罚除以单次费用上限。后续应将偏好尺度与预算准入分开，保持其他输入相同时，单纯提高预算不会改变已可用候选的价值排序。
- [固定画像](../../src/router/profiles.rs)按任务类型、角色、模型版本及验收版本选择质量证据；当前 Q 表示验收通过倾向，不等于连续产出质量或针对某项缺陷的成功概率。更细任务特征必须有明确的证据键和回退规则。
- [执行循环](../../src/engine/execution.rs)已有 cascade：确定性检查要求重试时，排除旧模型并设置不低于其 Q 的门槛。它不保证严格质量提升，也没有将 critic 评审自动接入 cascade。
- [宿主反馈](../usage.md#验收反馈与持久化指标)针对终态产物，影响后续任务；不能用现有 record_feedback 接口触发同一任务升级。运行中业务评价需要独立契约，不能混同历史反馈。
- 当前成本估计是本次调用预留依据，不能冒充整个协作方案的预期总成本。后者需要各阶段费用与条件失败概率；数据不足时应明确未知，并保留确定的剩余预算边界。

## 分阶段推进边界

### 第一阶段：可解释的任务选模与质量升级

先定义任务质量要求、独立成本偏好、升级最小改善要求，以及运行中评价的输入输出。复用 router 的纯决策边界、engine 的有界策略编排和 store 的事务边界；供应商协议仍只由 adapter 处理。

运行中评价须明确通过、可重试缺陷、缺失证据和人工介入；评审无工具权限。若调用模型评审，费用与调用次数必须先预留并计数；宿主评价涉及的成本、超时和取消也须显式定义。不得默认将模型自报 pass 当作可靠业务质量标签。

路由证据应解释所用质量证据、成本尺度、榜单贡献、升级原因、回退层级和排除理由。候选基础证据任务内固定；已产生缺陷作为本次决策输入持久化，不刷新任务中质量样本。

### 第二阶段：协作方案总成本与细粒度适配

基于独立业务验收数据评估不同难度、缺陷与协作路径的表现，再引入整个方案的费用估计。必须隔离模型版本、评价版本和策略条件，防止把只在简单任务上的成功率用于困难任务。未经过校准的估计只标注假设，不作为实测收益。

## 必须通过的验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 简单任务两模型质量接近但价格不同 | 按明确成本偏好选择较低成本候选 |
| 困难任务强模型质量优势显著 | 允许第一轮直接选择强模型 |
| 仅提高预算，候选集合未变 | 价值排序不因成本归一化变化而反转 |
| 均满足要求，额外质量收益很小而费用明显增加 | 不仅因质量分略高就选择昂贵候选 |
| 均满足最低要求，但任务重视的额外质量收益显著 | 在成本偏好允许时选择质量更高的候选，不机械选择最便宜者 |
| 强模型对所有当前任务的质量成本权衡均更好 | 允许集中选择，不施加强弱模型配额 |
| 初次产出质量不足，升级候选可用 | 评价记录、缺陷、下一次路由及最终产物可关联；调用和费用逐次入账 |
| 仅价格或外部名次更高 | 不足以独立证明质量升级 |
| 产出通过有效验收 | 不再发生升级调用 |
| 升级模型超预算或不满足数据约束 | 不派发，保留未达标产物和具体原因 |
| 没有更合适候选或额度耗尽 | 有界终止，无隐式重复重试 |
| 评价或升级期间取消、超时、费用未知 | 终态与清理完成；已知费用结算，未知费用保留 |
| 历史反馈到达正在运行任务期间 | 当前基础画像不变，只影响后续任务 |

第一阶段算法和接口见[具体方案](task-fit-routing-contract.md)，实现与验证证据见[实施记录](task-fit-routing-implementation.md)。技术图只展示已实现的任务价值评分和严格质量升级；后续语义 critic 与总成本预测仍保持为目标设计。

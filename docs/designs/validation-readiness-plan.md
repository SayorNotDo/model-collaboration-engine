## 目标与取舍

补足复杂协作的真实路径证据、明确精确计费缺口、提供自动检查和发布产物构建入口。此轮不改变内核策略、账本或数据库 schema，不发布软件包。

相比直接改执行内核，先通过公共 API 的独立探针定位缺口；相比直接按总 token 精算，离线核对明确要求缓存、时间和账单证据。缺失数据不能补成零，也不能回写真实账本。

## 独立任务及验收

- [x] `examples/collaboration_probe.py`、配套测试及设计说明：最多四个任务，分别验证级联、critic 修订、必需规划和宿主工具；保存配置、逐调用证据及终态。人为诱导的路径单列，不能声称自然质量收益。未知费用或账务错误停止后续派发，取消等待导出与关闭。
- [x] `examples/billing_audit.py`、配套测试及 `billing-precision.md`：核实官方费率与用量字段；精确小数计算，拒绝错误/缺失证据，区分估算、费率复算和供应商账单核对。
- [x] `.github/workflows/`、`LICENSE`、`docs/releasing.md`：Linux/Windows 离线质量门禁、手动产物构建；不读取供应商凭证，不自动上传包仓库。本地可检查工作流定义，远端执行必须单独报告。
- [x] `examples/benchmark_metrics.py`、配套测试：只在临时合成数据库测试 `Engine.metrics()` 的不同记录规模，校验计数和费用；记录平台、数据形状及耗时，不能外推生产 SLA。
- [x] `current-status.md` 和 README：按实现、离线证据、真实证据与缺口分别记录；历史设计保留但增加当前状态入口。

## 验证与交付

新增行为先测试失败，再实现并运行对应测试。最终按 `.agent/README.md` 运行 Python 全量、Ruff、文档链接与空白检查；原生代码若改变则重建并执行 Rust 检查。真实调用单独保存报告，核对 calls、settled、reserved 与 attempts。所有已产生费用证据均保留；提交、推送、发布不属于本轮交付。
